## ما هو

لعبة إدارة فندق ثنائية الأبعاد للهاتف بروح Playfish *Hotel City* (2010).
بحسب DEC-001 الهدف هو روح اللعبة لا مطابقة أرقامها حرفيًا؛ أرقام الأصل
(3أ/3ب) ما زالت هي الحالية حتى تُعاد صياغة الاقتصاد في P3.
الاتجاه البصري الملزم (DEC-008): واجهة أمامية مقطعية بأسلوب Chibi وباستيل
وخطوط داكنة وفق `docs/VISUAL_NORTH_STAR.jpeg`، وقواعد الإنتاج في
`docs/ART-0_VISUAL_DIRECTION_AR.md`.

**تعديل على DEC-007 منذ ART-6:** لم يعد هناك مورّد فن خارجي. كل الأصول —
257 ملفًا بدقتين — تُرسم داخل المستودع في `tools/art/` من نظام أسلوب واحد،
ويُعاد توليدها كلها بأمر واحد (`npm run gen:art`). السبب في
`docs/ART-6-REBUILD-REPORT.md` §1: الاتساق عبر مئتي صورة لا يأتي من جودة
صورة منفردة، بل من استحالة الوصول إلى لون خارج `hcstyle.py`.

## ما ينقص الآن (حسب المرجع)

1. **الديكور يُرسم بفنه الحقيقي منذ HC-P1-S4** — عشر قطع ART-1 داخل غرفة
   `economy` الجديدة، بمرساة ومقياس وطبقة وترتيب رسم مُختبرة. الباقي من
   الكتالوج (67 قطعة) ما زال يُرسم صندوقًا موسومًا حتى يسلّمه Codex في ART-2.
2. **لا مراجعة بصرية على قماشة Pixi حقيقية بعد**: هذه البيئة بلا معالج رسوم
   (DEC-009)، والدليل البصري الحالي تركيب حسابي من ملفات الفن
   (`docs/hc-p1-s4-shots/`). **فُتح الباب في 03-09-2026:** فعّل المالك Pages
   ونجح تشغيل النشر رقم 5، واللعبة حية على
   https://mf103871-boop.github.io/hotel-city-tycoon-lastest/ (BL-030
   `CLOSED`). المنشور هناك هو `main` **قبل** S4، فمراجعة فن الديكور على
   الهاتف تنتظر دمج فرع S4.
3. لا thumbnails للديكور في المتجر/البناء/المخزن — **الملفات العشرون موجودة
   على القرص منذ ART-1** لكن لا manifest يعلنها ولا واجهة تستعملها؛ ولا
   `MOVE_DECOR`/`FLIP_DECOR` ولا واجهة تحريك/قلب. هذه هي الخطوة S5.
4. القطع لا تتفادى التداخل بعد: المراسي تُصفّ كل 8px فتركب (BL-031).
5. عيوب §4G في المرجع: الشبح عند بيع الغرفة والتخزين السلبي لفشل الأصول
   **أُغلقا في تدقيق 03-09-2026**؛ تبقى مهلة المفتش ومستورد الحفظ.
6. سجل المؤجل §13: BL-001..005، BL-015، BL-017، BL-019..029، والجديد
   BL-031..033 من S4.

## البنية

```
data/          16 ملف توازن — مصدر الحقيقة، لا رقم واحد في الكود
src/core/      المحاكاة: نقية، حتمية، بلا Pixi ولا React ولا DOM ولا ساعة
src/bridge/    الجسر: المحرك، المتجر، الانتقاءات، الشخصيات، الإشعارات
src/render/    Pixi v8: كاميرا، قص، تجميع، إيماءات، شخصيات متحركة
src/ui/        React: لوحات، أوراق، إشعارات، إعدادات
src/save/      IndexedDB + ترحيلات (SCHEMA_VERSION 18) + تصدير/استيراد
src/audio/     WebAudio، مدير واحد
tools/         مولّدات، مُدقّقات، محاكيا توازن، الفحص الذاتي، لقطات خط الأساس
tests/         unit (vitest) · determinism · e2e (Playwright: desktop + phone)
docs/          المرجع + تقارير الخطوات؛ docs/history للأرشيف
```

قاعدتان يفرضهما ESLint كأخطاء: النواة لا تستورد مُصيِّرًا ولا إطار عمل ولا
تقرأ ساعة؛ والواجهة لا تصل إلى النواة إلا عبر الجسر.

## الأصول

257 مدخلًا في `public/assets/manifest.json` (115 غرفة، 93 ديكور، 36 شخصية،
6 مؤثرات، 7 واجهة)، **كلها موجودة بدقتي 1× و2×**، فصارت `resolutions` تعلن
`[1, 2]`. المولّد لا يعلن إلا الطبقات المكتملة على القرص، والمحمّل يرجع إلى 1×
لكل ملف يغيب في طبقة أعلى.

كلها مرسومة داخل المستودع (`tools/art/`) ويعاد توليدها بـ`npm run gen:art`؛
تفاصيل العقد في `ASSET-SPEC.md` وأوراق المعاينة في `docs/art-preview/`.

## الأوامر

```bash
npm ci                   # lockfile: package-lock.json (npm) — واحد فقط، مولّد على Node 22
npm run dev
npm run verify           # بيانات + أنواع + lint + وحدة + الفحص الذاتي
npm run test:e2e         # 41 سيناريو × مشروعان؛ يعمل في CI (docs/CI-E2E.md)
npm run gen:assets       # يعيد توليد manifest من data/ ومن الشجرة على القرص
npm run gen:art          # يعيد رسم كل الفن بدقتين ثم يولّد manifest
npm run art:preview      # أوراق معاينة إلى docs/art-preview/ (rooms|decor|cast|icons|facade)
npm run build            # validate → tsc → vite → ختم إصدار SW → الميزانية → لا كود غش
```
