## ما هو

لعبة إدارة فندق ثنائية الأبعاد للهاتف بروح Playfish *Hotel City* (2010).
بحسب DEC-001 الهدف هو روح اللعبة لا مطابقة أرقامها حرفيًا؛ أرقام الأصل
(3أ/3ب) ما زالت هي الحالية حتى تُعاد صياغة الاقتصاد في P3.
الاتجاه البصري الملزم (DEC-008): واجهة أمامية مقطعية بأسلوب Chibi وباستيل
وخطوط داكنة وفق `docs/VISUAL_NORTH_STAR.jpeg`، وقواعد الإنتاج في
`docs/ART-0_VISUAL_DIRECTION_AR.md`. Codex يصنع كل الفن والأنيميشن؛ Fable
يكتب المواصفات ويدمج برمجيًا فقط (DEC-007).

## هل تعمل؟

- **بلا متصفح:** نعم. `npm run verify` = بيانات + أنواع + lint + وحدة + الفحص
  الذاتي (28 وحدة، 630 فحصًا بعد S2).
- **في المتصفح عبر CI:** نعم منذ S8 على GitHub Actions (`docs/CI-E2E.md`).
  ستة إخفاقات مصنفة؛ أربعة أُصلحت في S9، واثنان (أصول `phone`) عولج سببهما
  في S2 وينتظران تشغيل CI.
- **التحقق البصري للقماشة (PixiJS):** لا يتم في CI بقرار DEC-009 (خوادم بلا
  GPU)؛ يتم على أجهزة حقيقية ضمن مراجعات Codex البصرية.

## ما ينقص الآن (حسب المرجع)

1. **ART-1 لم يُسلَّم** من Codex (`docs/ASSET_REQUEST-ART-1.md`).
2. **الديكور غير مرئي**: `PlacedDecor` = `slot` فقط؛ لا يصل إلى
   `SceneSnapshot` ولا يرسمه `RoomView`؛ لا migration 17→18 بعد.
3. لا thumbnails للديكور في المتجر/البناء/المخزن، ولا دورة شراء/وضع/تحريك/
   قلب/تخزين/بيع مرئية.
4. عيوب §4G في المرجع (الشبح عند بيع الغرفة، مهلة المفتش، مستورد الحفظ، التخزين
   السلبي لفشل الأصول) — مسجلة، لم تُعالَج.
5. سجل المؤجل §13: BL-001..005، BL-015، BL-017.

## البنية

```
data/          16 ملف توازن — مصدر الحقيقة، لا رقم واحد في الكود
src/core/      المحاكاة: نقية، حتمية، بلا Pixi ولا React ولا DOM ولا ساعة
src/bridge/    الجسر: المحرك، المتجر، الانتقاءات، الشخصيات، الإشعارات
src/render/    Pixi v8: كاميرا، قص، تجميع، إيماءات، شخصيات متحركة
src/ui/        React: لوحات، أوراق، إشعارات، إعدادات
src/save/      IndexedDB + ترحيلات (SCHEMA_VERSION 17) + تصدير/استيراد
src/audio/     WebAudio، مدير واحد
tools/         مولّدات، مُدقّقات، محاكيا توازن، الفحص الذاتي، لقطات خط الأساس
tests/         unit (vitest) · determinism · e2e (Playwright: desktop + phone)
docs/          المرجع + تقارير الخطوات؛ docs/history للأرشيف
```

قاعدتان يفرضهما ESLint كأخطاء: النواة لا تستورد مُصيِّرًا ولا إطار عمل ولا
تقرأ ساعة؛ والواجهة لا تصل إلى النواة إلا عبر الجسر.

## الأصول

241 مدخلًا في `public/assets/manifest.json` (115 غرفة، 77 ديكور، 36 شخصية،
6 مؤثرات، 7 واجهة)، كلها موجودة بدقة 1×. **لا توجد شجرة `@2x` بعد**؛ منذ
S2 لا يعلن المولّد إلا الطبقات المكتملة على القرص، والمحمّل يرجع إلى 1× لكل
ملف يغيب في طبقة أعلى. عند تسليم 2× يكفي وضع الملفات تحت
`public/assets/@2x/` ثم `npm run gen:assets`.

## الأوامر

```bash
npm ci                   # lockfile: package-lock.json (npm) — واحد فقط
npm run dev
npm run verify           # بيانات + أنواع + lint + وحدة + الفحص الذاتي
npm run test:e2e         # 41 سيناريو × مشروعان؛ يعمل في CI (docs/CI-E2E.md)
npm run gen:assets       # يعيد توليد manifest من data/ ومن الشجرة على القرص
npm run build            # يفشل إن تجاوزت الميزانية أو بقي كود غش
```
