# النشر — والتأكد أنه حدث

## ما قاله التقرير

```
build 0.1.0+20260829T0829
```

**مطابق حرفياً لتقرير المرة الماضية.** فالنسخة الحيّة لم تتغيّر، وكل ما بعد
البند السادس في ذلك التقرير أثر نشرٍ لم يحدث لا أعطال:

- `window.hct.perf` شُحن الساعة 09:46، والبناء الحيّ من 08:29
- وضع الضغط، وسطر الذاكرة في الشارة، وإصلاح `.gitignore` — كلها بعده

**البصمة أدّت الغرض التي بُنيت لأجلها:** سطر واحد أنهى السؤال بلا تخمين.

---

## ثلاثة أشياء أضفتها لئلا يتكرّر

### 1. عامل الخدمة لم يعد يخزّن شيفرة التطبيق

قاعدة «من الذاكرة أولاً» كانت `/assets/` — **وهو أيضاً حيث تضع Vite حزمة
JavaScript.** تجزئة أسماء الملفات كانت تُنقذنا عادةً، لكن طبقة تخزين تعمل
بالمصادفة ليست تصميماً. **وحزمة قديمة من الذاكرة تبدو تماماً كنشرٍ لم يحدث.**

صارت القاعدة تسمّي مجلدات الفن والصوت صراحةً. والشيفرة من الشبكة دائماً.

### 2. مخرج طوارئ بلا أدوات مطوّرين

```
?fresh=1
```

يُلغي تسجيل كل عامل خدمة، ويمسح كل ذاكرة مؤقتة، ثم يعيد التحميل. **يُنهي سؤال
«هل النسخة الجديدة حيّة فعلاً» بجواب قاطع بدل نظرية.**

### 3. البصمة مرئية بلا وحدة تحكم

صارت تظهر تحت مؤشر التحميل مباشرة. تفتح الرابط وتقرأها في ثانية.

---

## خطوات النشر

```bash
npm install
npm run build
```

**قبل الرفع، تحقق:**

```bash
ls dist/assets/characters/*_walk.png | wc -l     # يجب أن يطبع 20
```

وسطر البناء نفسه يفشل إن نقص شيء:

```
✓ assets shipped    263 /   263
```

**ثم ارفع محتوى `dist/` كاملاً.**

## التحقق — عشر ثوانٍ

افتح الرابط هكذا:

```
?fresh=1
```

سيمسح كل شيء قديم ويعيد التحميل. ثم انظر تحت مؤشر التحميل: **بصمة البناء**.

يجب أن تكون **أحدث من `20260829T0829`**. إن كانت هي نفسها، فالنشر لم يصل
للخادم أصلاً والمشكلة في خط الرفع لا في اللعبة.

بعدها فقط أرسل الوكيل — قبلها هو مضيعة للوقت.

---

## وحين يصل النشر

الخطوة الوحيدة التي تهمّني هي هذه، **من هاتفك**:

```
?stress=60&debug=1
```

اسحب وكبّر عشرين ثانية، ثم في وحدة التحكم:

```js
await window.hct.perf()
```

هذه القراءة تُغلق ثلاثة معايير خروج معاً: **P3 و P5 و P7**.
