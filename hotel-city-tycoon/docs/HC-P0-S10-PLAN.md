# HC-P0-S10 — أساس التنفيذ على iPhone وAndroid

التاريخ: 07-09-2026 — الحالة عند بدء التنفيذ: `IN_PROGRESS`.

## فحص المرجع

- قُرئ المرجع v1.2 كاملًا، ودليل ART-0، وحالة المشروع والكود المرتبط.
- المرحلة: P0، تثبيت بيئة التنفيذ. P1 وP2 باقيتان `IN_PROGRESS`.
- الهدف الواحد: جعل المشروع الحالي أساسًا قابلًا للبناء لتطبيقَي الهاتف بالاتجاهين، مع تثبيت عقد الإنتاج البصري المعتمد.
- المشكلة: المشروع ويب فقط؛ لا مشاريع أصلية، وmanifest يقفل الاتجاه عموديًا، والمساحات الآمنة لا تغطي جميع الجهات.
- التفويض: المالك اختار تطبيق iPhone وAndroid «من البداية»، ودعم الاتجاهين، وتنفيذ Codex مباشرة داخل المستودع. يحل هذا محل توزيع التنفيذ القديم، ويضيف إعداد المنصة إلى خط الأساس؛ لا يعني إغلاق P8.
- خط الأساس: main عند `1b05c1562f51c59a1652f3994c6a52169c57afca`؛ تحقق المراجعة السابق: 82 Vitest + 776 selftest، والبناء ناجح، 4 تحذيرات lint.
- صورة الأسلوب المعتمدة في حوار المالك ستُحفظ في docs كمرجع؛ ليست أصلًا مشحونًا داخل الفندق.

## النطاق وخطوة التنفيذ

تثبيت قرارات المالك في سجل المرجع والخطة الرسمية، توثيق مواصفات عينة الاستقبال/المصعد/غرفة النوم، ثم إضافة Capacitor ومشروعَي Android وiOS وbuild/sync واضحين، وإزالة قفل الاتجاه ومعالجة safe-area واللوحات القصيرة وتغير مساحة القماشة. الملفات المتوقعة: package وlockfile، إعداد Capacitor، مجلدا ios/android، vite/main/CSS/App/Sheet/HotelCanvas/Hud عند الحاجة، الوثائق واختبار تدوير محدد.

لا تغيير في المحاكاة أو الاقتصاد أو صيغة الحفظ أو كتالوج الفن. عيب تحديث الديكور ART-REFRESH وإنتاج رسومات العينة يبقيان للمهمة البصرية التالية. لا حسابات أو مشتريات أو إعلانات أو نشر متجر ضمن هذه الخطوة.

## شروط القبول والأدلة

1. قرارات المنصة والاتجاه والمسؤولية والصورة موثقة بلا تعارض صامت مع التاريخ.
2. مشاريع أصلية قابلة للمزامنة من نسخة إنتاج محلية، بلا server.url خارجي أو مفتاح توقيع ملتزم.
3. iPhone وAndroid يسمحان بالطول والعرض؛ قوائم اللعبة قابلة للتمرير عند قصر الشاشة، والحواف تراعي النتوء وشريط الإيماءات.
4. لا Service Worker لنسخة التطبيق المجمعة؛ مسار الويب يبقى متاحًا للمعاينة.
5. verify وbuild ثم sync، وفحص إعدادات المنصتين، واختبار متصفح محدد لتغيير الأبعاد وفتح القوائم واستمرار الحالة. نجاح المتصفح ليس اعتماد هاتف فعلي.
6. تقرير صريح لما لم يمكن تشغيله: بناء iOS يحتاج macOS/Xcode؛ Android يحتاج SDK/JDK. لا وعود بتجربة جهاز لم تُجر.

## المخاطر والرجوع

الهوية `com.hotelcitytycoon.app` مؤقتة للتطوير حتى تثبيت هوية المتاجر قبل أول توزيع. حفظ النسخة الأصلية على أصل محلي مختلف عن Pages؛ لا يُدّعى نقل حفظ الموقع تلقائيًا. لا تغيير في schema 18. يمكن التراجع عن الفرع قبل أي توزيع من دون ترحيل بيانات. القياسات الحالية تحدد ميزانية JS والفن؛ يُشغّل حارس الميزانية بعد البناء.

## مطابقة الخطة مع المرجع

- P0 أساس المنصة، بناء على قرارات المالك الحالية؛ تجهيز تطبيقَي الهاتف لا يعني الانتقال إلى اعتماد إطلاق P8.
- عقد العينة تفصيل للاتجاه المعتمد فقط؛ لا إنتاج جماعي أو تغيير توازن.
- كل مخرج قابل للفحص؛ أُعلن قيد بيئة بناء الهاتف الفعلية.
- القرار: صالحة للتنفيذ. تُسجّل النتائج بعد تشغيلها، ويظل اعتماد الأجهزة والفن منفصلًا.
