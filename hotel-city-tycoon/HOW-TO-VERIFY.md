# كيف تفحص التسليم

خمس دقائق. الترتيب مهم: لا تنتقل لخطوة قبل نجاح التي قبلها.

---

## 1. التثبيت

ارفع الـzip إلى Replit واضغط **Run**، أو يدوياً:

```bash
npm install
```

**النجاح:** ينتهي بلا `ERR!` أحمر.
**الفشل:** الصق لي آخر 20 سطراً.

---

## 2. الفحوص بلا متصفح — الأهم

```bash
npm run test:selftest
```

**يجب أن ترى ثلاث كتل تنتهي بـ:**

```
  29 checks passed     ← النواة
  24 checks passed     ← طبقة التشغيل
  21 checks passed     ← رياضيات العرض
```

**74 فحصاً.** هذه شغّلتها أنا بالفعل، فوجودها خضراء عندك يعني أن بيئتك سليمة.
أي رقم أقل = مشكلة في بيئتك لا في الكود، وأريد أن أعرف.

---

## 3. الفحوص التي لم أستطع تشغيلها

```bash
npm run verify
```

يشغّل: تحقق البيانات ← الأنواع ← ESLint ← Vitest.

**هذه أول مرة تُشغَّل فيها `typecheck` و `lint` و `vitest` منذ P1.** أرجّح ظهور
أخطاء أنواع. **الصقها كما هي وأصلحها فوراً** — هذا متوقّع، لا فشل.

---

## 4. اختبار حدود الطبقات

الاختبار الذي طلبته منك منذ P1:

```bash
echo "import React from 'react';" >> src/core/rng/index.ts
npm run lint
```

**النجاح:** يفشل برسالة `src/core must not import React`.
**الفشل:** إن مرّ بلا خطأ، فالقاعدة معطوبة وأريد أن أعرف فوراً.

ثم تراجع:

```bash
git checkout src/core/rng/index.ts   # أو احذف السطر يدوياً
```

---

## 5. التشغيل

```bash
npm run dev
```

افتح المعاينة. **لن تحتاج للتنقيب في الكود** — أضفت شارة تُبلغك بنفسها في أعلى
يسار الشاشة:

```
renderer  webgpu     ← أو webgl
fps       60
rooms     4/4 drawn
zoom      1.00×
```

انقر عليها لتصغيرها.

### ماذا يعني كل سطر

| السطر | جيد | مقبول | مشكلة |
|---|---|---|---|
| `renderer` | `webgpu` أخضر | `webgl` كهرماني — السقوط يعمل، وهذا نجاح أيضاً | فارغة = التهيئة فشلت |
| `fps` | 55+ أخضر | 40–55 كهرماني | أقل من 40 أحمر |
| `rooms` | العدد المرسوم أقل من الإجمالي عند التقريب | — | متساويان دائماً = القص لا يعمل |

**افتح وحدة التحكم (Console)** وابحث عن:

```
[hotel-city-tycoon] renderer: webgpu, resolution 2x
```

---

## 6. الاختبار على هاتف حقيقي — لا تتخطَّ هذه

سطح المكتب لا يخبرك شيئاً عن الأداء ولا يختبر اللمس إطلاقاً.

Replit يعطيك رابطاً عاماً. افتحه على هاتفك، ثم:

| الإيماءة | المتوقّع |
|---|---|
| سحب بإصبع | الفندق يتحرك، **ولا يمكن دفعه خارج الشاشة** |
| تقريب بإصبعين | يكبّر، **والنقطة تبقى تحت أصابعك ولا تنزلق** |
| نقرة على غرفة | تُسجَّل كنقرة لا كسحب |
| دوران الجهاز | لا ينكسر التخطيط |
| زر العربية | الواجهة تنقلب لليمين، **والكانفاس لا ينقلب** |

راقب الـfps أثناء السحب لا أثناء السكون.

## 7. اختبار الحفظ

أهم اختبار وظيفي:

1. اضغط **Open hotel** وابنِ عدة غرف
2. **أغلق التبويب تماماً**
3. أعد فتحه

**النجاح:** غرفك موجودة، وعملاتك زادت أثناء غيابك.
**الفشل:** فندق جديد فارغ = الحفظ لا يعمل.

جرّب أيضاً: أبقِ الفندق مفتوحاً، أغلق التبويب 10 دقائق، ثم عد. يجب أن تجد
دخل الغياب مضافاً.

## ما أحتاجه منك

أربعة أسطر تكفي:

```
1. test:selftest:  74/74 ✅  أو  العدد + الخطأ
2. verify:         ✅  أو  الصق الأخطاء
3. renderer:       webgpu / webgl / فشل
4. fps على الهاتف: ___ أثناء السحب
```

وإن انكسر شيء، **الصق الخطأ كما هو حرفياً**. لا تلخّصه.
