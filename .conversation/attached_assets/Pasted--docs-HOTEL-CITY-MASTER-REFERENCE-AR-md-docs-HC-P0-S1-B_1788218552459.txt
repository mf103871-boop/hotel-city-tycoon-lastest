اقرأ docs/HOTEL_CITY_MASTER_REFERENCE_AR.md كاملًا وdocs/HC-P0-S1-BASELINE.md قبل أي عمل. نفّذ الآن HC-P0-S2 وحدها: إزالة عائق بيئة Chromium الذي أثبته HC-P0-S1 (البند HC-P0-S1-BL-001) حتى ينفّذ npm run test:e2e اختبارات فعلية، ثم استكمال الدليل المؤجل HC-P0-S1-BL-002. ابدأ بقسم «فحص المرجع» ثم قالب الخطة ثم «مطابقة الخطة مع المرجع» قبل التنفيذ. ممنوع تعديل src/ أو data/ أو package-lock.json أو منطق أي اختبار في tests/e2e؛ التعديل الوحيد المسموح به في الكود هو ملف playwright.config.ts بالإضافة المحروسة المحددة أدناه. ممنوع توليد أي صور أو رسوم أو sprite sheets أو animation.

أولًا شخّص العائق كاملًا بدل مطاردة مكتبة واحدة: اعرض محتوى ~/.cache/ms-playwright لتحديد مجلد chromium، ثم نفّذ ldd على ملف chrome التنفيذي داخله، ورشّح الأسطر التي تحوي not found، وسجّل القائمة كاملة حرفيًا في التقرير.

المسار الأساسي أ: ثبّت عبر أداة تبعيات النظام في Replit حزمة chromium نفسها، فهي مبنية على Nix بمكتبات موصولة ذاتيًا ولا تحتاج مطاردة تبعيات. تحقق بالأمرين command -v chromium وchromium --version وسجّل ناتجهما. ثم أضف داخل كائن use في playwright.config.ts هذه الإضافة المحروسة حرفيًا من دون أي تغيير آخر في الملف:

...(process.env.PLAYWRIGHT_CHROMIUM_PATH
  ? { launchOptions: { executablePath: process.env.PLAYWRIGHT_CHROMIUM_PATH } }
  : {}),

ثم شغّل:

PLAYWRIGHT_CHROMIUM_PATH="$(command -v chromium)" npm run test:e2e

إن فشل الإطلاق برسالة تخص sandbox أو zygote أو namespaces حصرًا، أضف داخل نفس الحارس chromiumSandbox: false وسجّل ذلك صراحة في التقرير، ثم أعد الأمر نفسه.

المسار البديل ب، فقط إن تعذر تثبيت حزمة chromium من الأداة: من قائمة not found التي جمعتها، ثبّت الحزم المقابلة دفعة واحدة عبر أداة التبعيات — libgbm توفرها mesa، وعادة تلزم أيضًا libxkbcommon وpango وcairo وcups وdbus وexpat وnspr وnss ومكتبات xorg مثل libX11 وlibXcomposite وlibXdamage وlibXext وlibXfixes وlibXrandr وlibxcb — ثم أعد ldd وأعد npm run test:e2e. إن بقيت أسطر not found بعد محاولتين، توقف وسجّل الحالة BLOCKED بالقائمة المتبقية ولا تكتب PASS.

عند نجاح الإطلاق: شغّل npm run test:e2e كاملًا وسجّل حرفيًا: المخطط 82، المنفذ فعليًا، الناجح والفاشل لكل مشروع من desktop وphone، المدة الكلية، وأسماء الاختبارات الفاشلة إن وجدت. ممنوع إصلاح أي فشل تطبيقي في هذه الخطوة؛ أضف كل فشل إلى جدول المؤجل بمعرّف جديد ووصف وخطورة ومرحلة مقترحة.

ثم أغلق HC-P0-S1-BL-002: التقط عبر Playwright لقطات مرجعية فعلية من اللعبة الحية للشاشة الرئيسية ولوحة البناء ومتجر الديكور ولوحة الإدارة وعرض هاتف Pixel 7، واحفظها في docs/baseline-screens/ بأسماء واضحة وسجّل مساراتها. ممنوع استخدام أي صورة ليست من جلسة المتصفح.

أنشئ docs/HC-P0-S2-REPORT.md بالنتائج الحرفية: قائمة ldd قبل الإصلاح وبعده، أسماء الحزم المضافة كما ثبتتها الأداة وأي تغيير أحدثته الأداة في ملفات الإعداد، ناتج chromium --version، الفرق الكامل في playwright.config.ts، أرقام E2E التفصيلية، ومسارات اللقطات. حدّث «سجل الحالة الحالي» في المرجع: HC-P0-S1 يبقى بتقريره التاريخي، وHC-P0-S2 تُسجل VERIFIED فقط إذا نُفذت اختبارات فعلية والتُقطت اللقطات، وإلا BLOCKED بالسبب المحدد. اختم بـ«مطابقة التنفيذ مع المرجع» وأسطر نهاية الجلسة الخمسة، واذكر الخطوة التالية الوحيدة بناءً على النتائج الفعلية من دون تنفيذها.
