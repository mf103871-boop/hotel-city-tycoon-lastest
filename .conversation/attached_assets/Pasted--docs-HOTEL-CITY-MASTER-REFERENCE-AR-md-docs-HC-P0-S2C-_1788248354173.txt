اقرأ docs/HOTEL_CITY_MASTER_REFERENCE_AR.md وdocs/HC-P0-S2C-REPORT.md قبل أي عمل. نفّذ الآن HC-P0-S2D وحدها: تشخيص بروتوكولي لتجمد browserContext.newPage داخل المشغّل، ثم تجربة علاجين مستهدفين، وفتح المجموعة الكاملة واللقطات عند أول نجاح. ابدأ بقسم «فحص المرجع» ثم قالب الخطة ثم «مطابقة الخطة مع المرجع» قبل التنفيذ. ممنوع تعديل src/ أو data/ أو package-lock.json أو package.json أو منطق أي اختبار في tests/e2e. التعديلات الوحيدة المسموحة: حارس واحد جديد محدد أدناه في playwright.config.ts، وtools/baseline-shots.mjs عند نجاح الإثبات فقط. ممنوع توليد أي صور أو رسوم أو sprite sheets أو animation. ممنوع --disable-gpu. لا تشغّل خادمًا يدويًا مع الإعداد الرئيسي لأن reuseExistingServer=false.

حقائق معتمدة من تنقيب سجلات S2B وS2C يجب البناء عليها لا إعادة إثباتها: سطر إطلاق المتصفح متطابق حرفيًا بين المشغّل الفاشل وprobe الناجح، وchannel مطبق فعلًا داخل المشغّل؛ أثناء تجمد newPage ظهر GLib-GIO-CRITICAL خاص بـg_settings_schema_source_lookup ثم Network service crashed عند الإغلاق؛ سجل probe الناجح خالٍ من كليهما.

1) التشخيص البروتوكولي، تشغيلة واحدة لكل جانب:
الجانب الفاشل: env -u PLAYWRIGHT_CHROMIUM_PATH DEBUG=pw:protocol,pw:browser* PLAYWRIGHT_FULL_CHROMIUM=1 PLAYWRIGHT_DISABLE_DEV_SHM=1 PLAYWRIGHT_NO_CAPTURE=1 npx playwright test --project=desktop -g "boots past the loading screen" واحفظ السجل كاملًا في docs/HC-P0-S2D-protocol-runner.log. أثناء التجمد وقبل انقضاء المهلة، من طرفية ثانية خذ ثلاث عينات تفصل بينها خمس ثوانٍ بالأمر ps -eLo pid,ppid,stat,wchan,comm ثم رشّح أسطر chrome واحفظها في docs/HC-P0-S2D-ps-samples.txt.
الجانب الناجح للمقارنة: شغّل probe اللعبة الحية كما في S2B لكن بإضافة DEBUG=pw:protocol,pw:browser* واحفظ docs/HC-P0-S2D-protocol-probe.log.
حدد في التقرير من سجل المشغّل: هل أرسل Target.createTarget، وهل وصل رد أو حدث targetCreated، وأين انقطعت المحادثة بالحرف، وقارنها بتسلسل probe عند النقطة نفسها. وحدد من عينات ps هل توجد عمليات chrome بحالة D أو Z أو معرفات network service تتبدل أثناء التجمد.

2) العلاج M1 بلا أي تعديل كود: أعد أمر الجانب الفاشل نفسه بإضافة GSETTINGS_BACKEND=memory إلى البيئة واحفظ docs/HC-P0-S2D-M1.log. إن نجح فانتقل إلى الخطوة 5 بهذه التركيبة.

3) العلاج M2: أضف في playwright.config.ts داخل use بعد الحراس الحاليين هذا الحارس حرفيًا من دون أي تغيير آخر:

...(process.env.PLAYWRIGHT_EXTRA_ARGS
  ? { launchOptions: { args: ['--disable-dev-shm-usage', ...process.env.PLAYWRIGHT_EXTRA_ARGS.split(' ')] } }
  : {}),

ثم أعد أمر الجانب الفاشل بإضافة PLAYWRIGHT_EXTRA_ARGS=--no-proxy-server واحفظ docs/HC-P0-S2D-M2.log. إن نجح فانتقل إلى الخطوة 5.

4) العلاج M3: أعد الأمر بإضافة الاثنين معًا GSETTINGS_BACKEND=memory وPLAYWRIGHT_EXTRA_ARGS=--no-proxy-server واحفظ docs/HC-P0-S2D-M3.log. إن فشلت M1 وM2 وM3 جميعًا فتوقف وسجّل BLOCKED، وضمّن في التقرير موضع انقطاع البروتوكول بالحرف وحالة العمليات من العينات، واعرض على المالك قرارين مؤجلين بلا تنفيذ: نقل E2E إلى GitHub Actions مع مخطط workflow مقترح نصًا، أو خطوة S2E لمحاول
